# Express + MongoDB Together — Notes

This section connects everything from the previous three sections into one working system. This is the architecture almost every real-world Node.js backend follows.

---

## 1. The Big Picture

```
Client
   ↓
Route
   ↓
Controller
   ↓
Mongoose Model
   ↓
MongoDB
   ↓
Response
   ↓
Client
```

Each layer has **one job**, and only talks to the layer directly next to it:

| Layer | Job |
|---|---|
| **Client** | Sends an HTTP request (browser, mobile app, Postman) |
| **Route** | Matches the URL + method, forwards the request to the right controller |
| **Controller** | Contains the logic — decides what to do, talks to the model |
| **Model** | Represents a MongoDB collection; defines structure and provides methods to query/update data |
| **MongoDB** | Actually stores and retrieves the data |
| **Response** | The data/result travels back up the same chain to the client |

This is essentially a simplified version of the **MVC (Model-View-Controller)** pattern, minus the "View" (since APIs return JSON, not rendered pages).

**Why separate things this way?**
- Each file stays small and focused (easier to read/debug).
- Logic is reusable and testable independently.
- Multiple developers can work on different layers without conflicts.

## 2. Mongoose — the Bridge Between Express and MongoDB

**Mongoose** is an **ODM** (Object Data Modeling) library — it sits between your Express app and MongoDB, letting you interact with the database using JavaScript objects, schemas, and models instead of writing raw MongoDB queries everywhere.

Why use Mongoose instead of the raw MongoDB driver:
- Lets you define a **schema** — enforcing structure even though MongoDB itself doesn't require one.
- Provides built-in **validation** (e.g., "email is required," "age must be a number").
- Gives you convenient methods like `.find()`, `.findById()`, `.save()` that map to MongoDB operations.
- Supports **middleware/hooks** (e.g., run code automatically before saving a document).

### Connecting to MongoDB

```js
const mongoose = require('mongoose');

mongoose.connect('mongodb://localhost:27017/myAppDB')
  .then(() => console.log('MongoDB connected'))
  .catch((err) => console.error('Connection error:', err));
```

- `mongoose.connect(uri)` — establishes a connection to a MongoDB database (local or cloud, e.g. MongoDB Atlas).
- Returns a **Promise**, so `.then()`/`.catch()` (or `async/await`) handles success/failure.

## 3. Schema and Model

A **schema** defines the shape/structure of documents in a collection. A **model** is what you actually use to interact with that collection (query, create, update, delete).

```js
// models/User.js
const mongoose = require('mongoose');

const userSchema = new mongoose.Schema({
  name: { type: String, required: true },
  email: { type: String, required: true, unique: true },
  age: { type: Number, min: 0 },
  createdAt: { type: Date, default: Date.now }
});

const User = mongoose.model('User', userSchema);

module.exports = User;
```

**Explaining each part:**
- `new mongoose.Schema({...})` — defines the fields each document should have, their types, and validation rules (`required`, `unique`, `min`, `default`, etc.).
- `mongoose.model('User', userSchema)` — compiles the schema into a **Model**. The string `'User'` tells Mongoose to look for (or create) a MongoDB collection called `users` (Mongoose automatically lowercases and pluralizes the name).
- The exported `User` object is what you'll actually use in your controllers to run queries — `User.find()`, `User.findById()`, `User.create()`, etc.

## 4. Full Example Flow — `GET /api/users`

Let's build out the exact example from your outline, one file at a time.

```
GET /api/users
       ↓
userRouter
       ↓
userController
       ↓
User.find()
       ↓
MongoDB
       ↓
JSON response
```

### Step 1 — The Model (`models/User.js`)
```js
const mongoose = require('mongoose');

const userSchema = new mongoose.Schema({
  name: { type: String, required: true },
  email: { type: String, required: true, unique: true }
});

module.exports = mongoose.model('User', userSchema);
```
This defines what a "User" document looks like and gives us a `User` model to query MongoDB with.

### Step 2 — The Controller (`controllers/userController.js`)
```js
const User = require('../models/User');

const getAllUsers = async (req, res) => {
  try {
    const users = await User.find();
    res.status(200).json(users);
  } catch (err) {
    res.status(500).json({ message: "Server error", error: err.message });
  }
};

module.exports = { getAllUsers };
```
**Explaining this:**
- `const User = require('../models/User')` — imports the Mongoose model, giving access to its query methods.
- `getAllUsers` is an **async function** — because talking to the database is asynchronous (see the Node.js notes on `async/await`).
- `await User.find()` — asks Mongoose to fetch **all documents** in the `users` collection. `User.find()` returns a Promise, so `await` pauses until MongoDB responds with the data.
- Wrapped in `try/catch` — if the database call fails (e.g. connection issue), the `catch` block runs instead of crashing the server.
- `res.status(200).json(users)` — sends the array of user documents back to the client as JSON with a `200 OK` status.
- `res.status(500).json({...})` — if something goes wrong, respond with a `500 Internal Server Error` and a helpful message.

### Step 3 — The Router (`routes/userRouter.js`)
```js
const express = require('express');
const router = express.Router();
const { getAllUsers } = require('../controllers/userController');

router.get('/', getAllUsers);

module.exports = router;
```
**Explaining this:**
- `express.Router()` creates a mini router (as covered in the Express notes).
- `router.get('/', getAllUsers)` — when a GET request hits the root of wherever this router is mounted, run `getAllUsers`. Note the router itself doesn't know the full path (`/api/users`) — that's decided when it's mounted in the main app file.

### Step 4 — Wiring It Up (`app.js` / `index.js`)
```js
const express = require('express');
const mongoose = require('mongoose');
const userRouter = require('./routes/userRouter');

const app = express();
app.use(express.json());

mongoose.connect('mongodb://localhost:27017/myAppDB')
  .then(() => console.log('MongoDB connected'))
  .catch((err) => console.error(err));

app.use('/api/users', userRouter);

app.listen(3000, () => console.log('Server running on port 3000'));
```
**Explaining this:**
- `app.use(express.json())` — middleware that parses incoming JSON request bodies into `req.body` (needed for POST/PUT/PATCH routes later).
- `mongoose.connect(...)` — establishes the database connection when the app starts.
- `app.use('/api/users', userRouter)` — mounts the router at the `/api/users` prefix. So `router.get('/', ...)` inside `userRouter.js` actually becomes reachable at **`GET /api/users`**.

### Tracing the request, step by step:
1. **Client** sends `GET /api/users`.
2. Express matches the path against `app.use('/api/users', userRouter)` and hands the request to `userRouter`.
3. Inside `userRouter`, the path `/` (relative to the mount point) matches `router.get('/', getAllUsers)`.
4. `getAllUsers` runs, calling `User.find()`.
5. Mongoose translates that into a MongoDB query and sends it to the database.
6. **MongoDB** returns matching documents.
7. Mongoose converts the raw BSON results into JavaScript objects and resolves the `await`ed Promise.
8. The controller sends them back with `res.status(200).json(users)`.
9. The **Response** (JSON array of users) travels back to the **Client**.

## 5. Extending to Full CRUD

Following the same pattern for the rest of the operations:

**Controller (`controllers/userController.js`):**
```js
const User = require('../models/User');

const getAllUsers = async (req, res) => {
  const users = await User.find();
  res.status(200).json(users);
};

const getUserById = async (req, res) => {
  const user = await User.findById(req.params.id);
  if (!user) return res.status(404).json({ message: "User not found" });
  res.status(200).json(user);
};

const createUser = async (req, res) => {
  const newUser = await User.create(req.body);
  res.status(201).json(newUser);
};

const updateUser = async (req, res) => {
  const updatedUser = await User.findByIdAndUpdate(req.params.id, req.body, { new: true });
  if (!updatedUser) return res.status(404).json({ message: "User not found" });
  res.status(200).json(updatedUser);
};

const deleteUser = async (req, res) => {
  const deletedUser = await User.findByIdAndDelete(req.params.id);
  if (!deletedUser) return res.status(404).json({ message: "User not found" });
  res.status(204).send();
};

module.exports = { getAllUsers, getUserById, createUser, updateUser, deleteUser };
```

**Router (`routes/userRouter.js`):**
```js
const express = require('express');
const router = express.Router();
const {
  getAllUsers, getUserById, createUser, updateUser, deleteUser
} = require('../controllers/userController');

router.get('/', getAllUsers);
router.get('/:id', getUserById);
router.post('/', createUser);
router.put('/:id', updateUser);
router.delete('/:id', deleteUser);

module.exports = router;
```

**Note on the Mongoose methods used above:**
| Method | Maps to |
|---|---|
| `User.find()` | Get all documents |
| `User.findById(id)` | Get one document by `_id` |
| `User.create(data)` | Insert a new document |
| `User.findByIdAndUpdate(id, data, { new: true })` | Update a document (`{ new: true }` returns the *updated* version, not the original) |
| `User.findByIdAndDelete(id)` | Remove a document |

*(These wrap the raw MongoDB CRUD operations from the MongoDB notes — `insertOne`, `find`, `updateOne`, `deleteOne` — with a friendlier, schema-aware interface.)*

## 6. Error Handling Reminder

Notice that in a real production app, you'd wrap these controller functions in `try/catch` (as shown in Step 2 above) or use an error-handling middleware to catch unhandled errors — otherwise, a database failure or invalid ID format (e.g., a malformed `ObjectId`) would crash the request instead of returning a clean error response.

A cleaner pattern often used in real projects — an **async wrapper** to avoid repeating `try/catch` everywhere:
```js
const asyncHandler = (fn) => (req, res, next) => {
  Promise.resolve(fn(req, res, next)).catch(next);
};

const getAllUsers = asyncHandler(async (req, res) => {
  const users = await User.find();
  res.status(200).json(users);
});
```
Any error thrown inside `getAllUsers` gets passed to `next()`, which forwards it to your error-handling middleware (covered in the Express notes).

---

## Quick Recap

- **Flow:** Client → Route → Controller → Model (Mongoose) → MongoDB → Response → Client
- **Mongoose** = the ODM library that connects Express to MongoDB using schemas and models
- **Schema** = defines document structure/validation · **Model** = the tool used to query that collection
- **Router** = maps URL + method to a controller function
- **Controller** = contains the actual logic, calls Mongoose model methods, sends the response
- Mongoose model methods (`find`, `findById`, `create`, `findByIdAndUpdate`, `findByIdAndDelete`) map directly to MongoDB CRUD operations
- Always handle errors (`try/catch` or an async wrapper) since database calls can fail
