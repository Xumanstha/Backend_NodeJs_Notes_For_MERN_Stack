# Mongoose — Notes

> Note: this section digs deeper into Mongoose itself. Section 6 (Express + MongoDB Together) showed the full request flow using these same concepts — this section is the reference for *how Mongoose works* in detail.

---

## 1. What is Mongoose?

Mongoose is an **ODM (Object Data Modeling) library** for MongoDB, designed to be used with Node.js.

In plain terms: MongoDB by itself is schema-less and works with raw documents. Mongoose sits on top of it and lets you:
- Define a **schema** — the expected shape of your documents.
- Get built-in **validation** — reject bad data before it ever reaches the database.
- Work with **models** — clean, method-rich objects instead of writing raw MongoDB queries.
- Add extra behavior via **hooks/middleware** — e.g. automatically hash a password before saving.

Without Mongoose, you'd use the raw `mongodb` driver, which gives you direct access to MongoDB but no structure, validation, or convenience methods.

## 2. Connecting to MongoDB

```js
const mongoose = require('mongoose');

mongoose.connect('mongodb://localhost:27017/myAppDB')
  .then(() => console.log('Connected to MongoDB'))
  .catch((err) => console.error('Connection error:', err));
```

- `mongoose.connect(uri)` — opens a connection to a MongoDB database at the given URI. Returns a Promise.
- The URI format: `mongodb://<host>:<port>/<databaseName>` for local databases, or a longer connection string (with credentials) for cloud-hosted databases like **MongoDB Atlas**.
- Best practice: store the URI in an **environment variable** (see the Node.js notes) rather than hardcoding it:
```js
mongoose.connect(process.env.MONGO_URI);
```

You can also listen for connection events:
```js
mongoose.connection.on('connected', () => console.log('Mongoose connected'));
mongoose.connection.on('error', (err) => console.error('Mongoose error:', err));
```

## 3. Schema

A schema defines the **structure, types, and rules** for documents in a collection.

```js
const userSchema = new mongoose.Schema({
    name: String,
    email: String,
    age: Number
});
```

**Explaining every part:**
- `new mongoose.Schema({...})` — creates a new Schema instance, describing what fields a "User" document should have.
- `name: String` — this is **shorthand syntax**: it means the `name` field should be of type `String`. Mongoose also supports `Number`, `Boolean`, `Date`, `Array`, `ObjectId`, and more.
- Each key in the object (`name`, `email`, `age`) becomes a field in every document created from this schema.

This shorthand (`field: Type`) is convenient, but in real projects you'll usually use the **long form** to add validation rules, defaults, etc. (covered below):
```js
const userSchema = new mongoose.Schema({
  name: { type: String, required: true },
  email: { type: String, required: true, unique: true },
  age: { type: Number, min: 0 }
});
```

---

## 4. Model

A model is what you get when you **compile a schema** — it's the actual object you use to interact with the corresponding MongoDB collection.

```js
const User = mongoose.model("User", userSchema);
```

**Explaining this line:**
- `mongoose.model(name, schema)` — takes two arguments: a string name (`"User"`) and the schema to use.
- Mongoose automatically converts `"User"` into the actual MongoDB collection name: lowercased and pluralized → `users`.
- The returned value, `User`, is a **class-like object** — you use it to create, read, update, and delete documents in the `users` collection.

So the relationship is:
```
Schema  → defines structure
Model   → the tool you actually use to query the database
Document → a single instance/record created from the model
```

---

## 5. Documents

A document is a single instance created from a model — representing one actual record in MongoDB.

```js
const newUser = new User({
  name: "Alice",
  email: "alice@example.com",
  age: 25
});

console.log(newUser.name); // "Alice"

await newUser.save(); // writes it to MongoDB
```

- `new User({...})` — creates a new document **in memory** (not yet saved to the database).
- Documents are regular JavaScript objects with extra Mongoose-provided methods, like `.save()`, `.remove()`, and validation logic attached.
- Calling `.save()` sends the document to MongoDB and inserts it as an actual record.

You can also create-and-save in a single step (shown in the CRUD section below).

## 6. CRUD with Mongoose

Mongoose models provide methods that map onto MongoDB's CRUD operations, with a friendlier interface.

**Create:**
```js
const user = await User.create({ name: "Bob", email: "bob@example.com", age: 30 });

// or, equivalently:
const user2 = new User({ name: "Carol", email: "carol@example.com" });
await user2.save();
```

**Read:**
```js
const allUsers = await User.find();                  // all documents
const oneUser = await User.findOne({ name: "Bob" });  // first match
const byId = await User.findById("64fabc123456789");  // find by _id
```

**Update:**
```js
await User.updateOne({ name: "Bob" }, { $set: { age: 31 } });

const updated = await User.findByIdAndUpdate(
  "64fabc123456789",
  { age: 31 },
  { new: true } // return the updated document, not the original
);
```

**Delete:**
```js
await User.deleteOne({ name: "Bob" });
await User.findByIdAndDelete("64fabc123456789");
```

*(These methods internally use the same MongoDB operations from the MongoDB notes — `insertOne`, `find`, `updateOne`, `deleteOne` — just wrapped with schema validation and a nicer API.)*

## 7. Validation

Mongoose can automatically **reject invalid data** before it's saved, based on rules defined in the schema.

```js
const userSchema = new mongoose.Schema({
  name: { type: String, required: true },
  email: {
    type: String,
    required: true,
    unique: true,
    match: /.+@.+\..+/
  },
  age: { type: Number, min: 0, max: 120 }
});
```

Common validation options:
| Option | Meaning |
|---|---|
| `required: true` | Field must be present |
| `unique: true` | No two documents can share this value (requires an index) |
| `min` / `max` | Numeric range limits |
| `minlength` / `maxlength` | String length limits |
| `match: /regex/` | Value must match a regular expression |
| `enum: [...]` | Value must be one of a fixed set of options |

Example with `enum`:
```js
role: { type: String, enum: ["user", "admin", "editor"], default: "user" }
```

If validation fails, Mongoose throws a `ValidationError` instead of saving bad data:
```js
try {
  await User.create({ email: "not-an-email" }); // missing required "name"
} catch (err) {
  console.error(err.message); // describes exactly what failed
}
```

## 8. Default Values

You can specify a fallback value for a field if none is provided when a document is created.

```js
const userSchema = new mongoose.Schema({
  name: { type: String, required: true },
  role: { type: String, default: "user" },
  isActive: { type: Boolean, default: true }
});
```

If you create a user without specifying `role`, Mongoose automatically sets it to `"user"`. Defaults can also be a **function**, evaluated at document-creation time:
```js
createdAt: { type: Date, default: () => Date.now() }
```

## 9. Timestamps

Instead of manually adding `createdAt`/`updatedAt` fields, Mongoose can manage them automatically via a schema option.

```js
const userSchema = new mongoose.Schema(
  {
    name: String,
    email: String
  },
  { timestamps: true }
);
```

- `{ timestamps: true }` — the second argument to `Schema()` is an **options object**.
- With this enabled, Mongoose automatically adds and maintains two fields on every document:
  - `createdAt` — set once, when the document is first created.
  - `updatedAt` — automatically updated every time the document is saved/modified.

This is extremely common in real projects — almost every schema uses `{ timestamps: true }`.

## 10. Schema Methods

You can attach **custom functions** directly onto documents (instance methods) or onto the model itself (static methods) — keeping related logic close to the schema.

**Instance method** (called on a single document):
```js
userSchema.methods.getGreeting = function () {
  return `Hello, my name is ${this.name}`;
};

const user = await User.findById(someId);
console.log(user.getGreeting()); // "Hello, my name is Alice"
```
- `userSchema.methods.<name>` — defines a method available on every document created from this schema.
- Inside the method, `this` refers to the specific document it was called on.
- **Note:** must use a regular `function () {}`, not an arrow function — arrow functions don't bind their own `this`, which would break access to the document's fields.

**Static method** (called on the model itself, not a specific document):
```js
userSchema.statics.findByEmail = function (email) {
  return this.findOne({ email });
};

const user = await User.findByEmail("alice@example.com");
```
Here, `this` refers to the **model** (`User`), not a document.

## 11. Middleware / Hooks

Mongoose middleware (also called "hooks") lets you run code **automatically before or after** certain operations — similar in spirit to Express middleware, but scoped to the schema/document lifecycle.

**Pre-hook** (runs before an operation):
```js
const bcrypt = require('bcrypt');

userSchema.pre('save', async function (next) {
  if (!this.isModified('password')) return next(); // only hash if changed
  this.password = await bcrypt.hash(this.password, 10);
  next();
});
```
- `userSchema.pre('save', ...)` — registers a function to run **before** every `.save()` call.
- `this` refers to the document being saved.
- `next()` — must be called to continue the save operation (same pattern as Express middleware).
- This is the standard pattern for automatically hashing passwords before storing them.

**Post-hook** (runs after an operation):
```js
userSchema.post('save', function (doc) {
  console.log(`User saved: ${doc.name}`);
});
```

Common hook types: `save`, `find`, `findOne`, `updateOne`, `deleteOne`, `validate` — each can have `pre` and `post` versions.

## 12. Population (`populate`)

Recall from the MongoDB notes: **references** store just an `_id` pointing to a document in another collection. `populate()` is Mongoose's way of automatically **replacing that `_id` with the actual referenced document**.

**Setting up a reference:**
```js
const postSchema = new mongoose.Schema({
  title: String,
  content: String,
  author: { type: mongoose.Schema.Types.ObjectId, ref: 'User' }
});

const Post = mongoose.model('Post', postSchema);
```
- `type: mongoose.Schema.Types.ObjectId` — this field stores an `_id`, not the full document.
- `ref: 'User'` — tells Mongoose *which model* this ID refers to, so it knows where to look when populating.

**Using `populate()`:**
```js
const post = await Post.findOne({ title: "My first post" }).populate('author');

console.log(post.author.name); // "Alice" — full user document, not just the ID
```

Without `.populate('author')`, `post.author` would just be the raw `ObjectId` string. With it, Mongoose runs a second query behind the scenes and swaps in the full document.

You can also populate only specific fields:
```js
.populate('author', 'name email'); // only include name and email, not the whole user document
```

## 13. Query Methods

Mongoose queries are **chainable** — most query methods return a query object that you can keep refining before it actually runs.

```js
const users = await User.find({ age: { $gte: 18 } })
  .select('name email')      // only return these fields
  .sort({ age: -1 })         // sort descending by age
  .limit(10)                 // max 10 results
  .skip(5);                  // skip the first 5 (pagination)
```

Common query methods:
| Method | Purpose |
|---|---|
| `.find(filter)` | Get all matching documents |
| `.findOne(filter)` | Get the first matching document |
| `.findById(id)` | Get a document by its `_id` |
| `.select(fields)` | Choose which fields to include/exclude |
| `.sort(fields)` | Order results (`1` = ascending, `-1` = descending) |
| `.limit(n)` | Cap the number of results |
| `.skip(n)` | Skip a number of results (pagination) |
| `.populate(field)` | Replace a referenced `_id` with the full document |
| `.exec()` | Explicitly execute the query, returning a real Promise (usually optional) |

**Important behavior:** a Mongoose query isn't actually sent to MongoDB until you `await` it (or call `.exec()`/`.then()`). This is what allows all the chaining above — you're building up the query, then triggering it at the end.

## Quick Recap

- **Mongoose** = ODM library connecting Node.js/Express to MongoDB with structure and convenience
- **`mongoose.connect()`** = opens the database connection
- **Schema** = defines fields, types, and rules · **Model** = compiled schema, used to query the collection · **Document** = one actual record
- **CRUD**: `create`/`save`, `find`/`findOne`/`findById`, `updateOne`/`findByIdAndUpdate`, `deleteOne`/`findByIdAndDelete`
- **Validation** (`required`, `unique`, `min/max`, `enum`) = rejects bad data automatically
- **Defaults** = fallback values for missing fields · **`timestamps: true`** = auto `createdAt`/`updatedAt`
- **Schema methods** = custom functions attached to documents (`.methods`) or models (`.statics`)
- **Middleware/hooks** (`pre`/`post`) = run code automatically around operations like `save`
- **`populate()`** = replaces a referenced `_id` with the actual linked document
- **Query methods** are chainable and only execute once `await`ed
